# 해설

```bash
du -sh ~/app/* ~/app/.[!.]*        # 숨김 폴더까지 폴더별 용량
du -ah ~/app | sort -h | tail -n 5  # 가장 큰 항목 5개
find ~/app -type f -size +50M       # 50MB 넘는 파일
ls -lh <찾은 경로>                  # 지우기 전에 확인
echo <찾은 경로> > ~/answer.txt
rm <찾은 경로>
```

## 기억할 것
- **위에서 아래로 좁혀 가기**: `df -h`(어느 디스크?) → `du -sh /*`(어느 폴더?) → `du -sh 폴더/*` 반복 → 범인 파일
- `du -sh *` 는 **숨김 폴더를 빠뜨립니다**. 실제 장애에서도 `.cache`, `.tmp` 같은 숨김 폴더가 범인인 경우가 많아요.
- `sort -h` 는 `1K`, `20M`, `3G` 같은 사람용 단위를 이해하고 정렬합니다. (`sort -n` 은 못 함)
- 실무 팁: 프로세스가 아직 열고 있는 파일을 `rm` 하면 **공간이 바로 돌아오지 않습니다**. 이럴 땐 `lsof +L1` 로 확인하고, 그 프로세스를 재시작하거나 `> 파일` 로 내용을 비우는(truncate) 방법을 씁니다.
