# 해설

```bash
cd ~/backup
nohup ./long-backup.sh > backup.log 2>&1 &
tail -f backup.log        # 보다가 Ctrl+C (백업은 계속 돌아요)
```

## 방법 비교
| 방법 | 터미널이 닫히면? | 메모 |
|---|---|---|
| `명령 &` | ❌ 같이 죽음 | 잠깐 다른 일 할 때만 |
| `nohup 명령 > 로그 2>&1 &` | ✅ 계속 | 가장 흔한 방법 |
| `명령 &` 후 `disown` | △ 셸은 SIGHUP 을 안 보내지만 프로그램은 여전히 SIGHUP 에 약함 | 이미 실행한 작업을 급히 살릴 때 |
| `setsid 명령 > 로그 2>&1 < /dev/null &` | ✅ 계속 | 터미널과 완전히 분리 |
| `tmux` / `screen` | ✅ 계속, **나중에 다시 붙어서** 볼 수 있음 | 대화형 작업에 최고 |
| systemd 서비스 | ✅ 재부팅 후에도 | 계속 돌아야 하는 서버 프로그램 |

## 이미 그냥 실행해 버렸다면?
```
Ctrl+Z        # 일시 정지
bg            # 백그라운드에서 계속
disown -h %1  # 터미널이 닫혀도 SIGHUP 을 보내지 않게
```

## 2>&1 의 순서
`> 로그 2>&1` 은 "출력은 로그로, 에러는 **출력이 가는 곳**으로" 라는 뜻이에요. `2>&1 > 로그` 로 쓰면 에러는 여전히 화면으로 가요. 리다이렉션은 왼쪽부터 차례로 적용돼요.

## 실무 팁
몇 시간짜리 작업(대용량 복사, DB 덤프, 마이그레이션)은 **tmux** 안에서 돌리는 습관을 들이세요. `tmux new -s backup` → 작업 실행 → `Ctrl+B` 후 `D` 로 빠져나오기 → 나중에 `tmux attach -t backup`.
