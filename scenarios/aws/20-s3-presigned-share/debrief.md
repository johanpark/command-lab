# 해설

```bash
aws s3 presign s3://finance-docs-XXXX/reports/2026-10-settlement.xlsx --expires-in 86400 > ~/share-url.txt
```

## 미리 서명된 URL 은 어떻게 동작하나
```
https://버킷.s3.../reports/2026-10-settlement.xlsx
  ?X-Amz-Credential=AKIA.../20261029/ap-northeast-2/s3/aws4_request   ← 누구 권한으로
  &X-Amz-Date=20261029T...Z  &X-Amz-Expires=86400                     ← 언제부터 몇 초
  &X-Amz-Signature=...                                                 ← 위 내용을 비밀 키로 서명
```
- S3 는 서명을 검증해서 **서명한 사람의 권한으로** 그 요청 하나만 허락해요. 파일·메서드(GET)·만료 시각을 바꾸면 서명이 깨져요.
- AWS 에 요청을 보내지 않고 **내 컴퓨터에서 계산만** 해서 만들어요. 그래서 링크를 만든 기록은 남지 않고, 다운로드할 때 접근 로그에 남아요.

## 주의할 점
- 링크를 가진 **누구나** 만료 전까지 열 수 있어요. 메일이 전달되면 그 사람도 열려요. 민감한 파일은 짧게.
- 서명한 사람의 권한이 사라지면(키 비활성화, 정책 제거) 링크도 바로 막혀요. 유효기간 전에 급히 막아야 할 때 쓸 수 있어요.
- IAM 사용자 키로 서명하면 최대 **7일**, 임시 자격 증명(역할, SSO)으로 서명하면 **그 자격 증명이 끝날 때** 링크도 끝나요.
- 반대로 **업로드용** 링크도 만들 수 있어요 (SDK 의 `generate_presigned_url('put_object', ...)` 나 presigned POST). 외부에서 파일을 받을 때 써요.

## 실무 팁
- 버킷은 이번처럼 **퍼블릭 액세스 차단을 켜 둔 채** 미리 서명된 URL 로만 공유하는 게 기본이에요.
- 자주 공유해야 하면 CloudFront 의 **서명된 URL/쿠키** 를 쓰면 더 세밀하게(IP 제한, 경로 단위) 제어할 수 있어요.
