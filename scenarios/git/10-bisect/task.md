# 40개 커밋 중 범인 찾기 (bisect)

`~/pricing` 저장소의 테스트(`./test.sh`)가 실패해요. 한 달 전 첫 커밋에서는 잘 됐다는데, 그 뒤로 **커밋이 40개**나 쌓였어요. 하나씩 확인하기엔 너무 많아요.

```
$ ./test.sh
✘ 할인가: 10000원 20% 할인 = 7999 (기대값 8000)
```

## 목표
1. 테스트가 **처음 깨진 커밋**의 해시(앞 7자리 이상)를 `~/answer.txt` 에 저장하세요.
2. 다 찾았으면 `main` 브랜치의 원래 위치로 돌아와 있어야 해요. (bisect 가 진행 중이면 안 돼요)

## git bisect
"여기선 됐고(good), 여기선 안 된다(bad)"를 알려주면, Git 이 **가운데 커밋**으로 이동해 주면서 범위를 반씩 줄여요. 40개도 6번 정도면 찾아요.

| 명령어 | 하는 일 |
|---|---|
| `git bisect start` | 시작 |
| `git bisect bad` | 지금 커밋은 깨져 있음 |
| `git bisect good 커밋` | 그 커밋은 정상 |
| `git bisect run ./test.sh` | 테스트를 **자동으로** 돌려서 찾기 |
| `git bisect reset` | 끝내고 원래 위치로 돌아가기 |
| `git log --oneline \| tail -1` | 첫 커밋 |
